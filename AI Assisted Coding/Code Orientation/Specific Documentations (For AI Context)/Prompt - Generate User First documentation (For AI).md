Prompt:
```
Review the application and create a product and UX design brief covering user needs, personas, goals, user stories, and the information and prerequisites needed to complete each workflow.

**Start with the available evidence**

Review the current interface, key screens, navigation, interactions, and user workflows. Inspect relevant code where needed to verify behavior, and review available product documentation and user research.

Identify the information needed to produce a reliable product analysis, such as user types, observed workflows, permissions, usage data, and user feedback. State which inputs are available and which are missing.

Ground findings in identifiable evidence. Distinguish directly observed behavior from inferences and unknowns. Use high, medium, or low confidence, and explain material uncertainty. Code can establish implemented behavior; it does not, by itself, establish users’ motivations or feelings.

When evidence is insufficient, provide the supported findings and identify what additional information would be needed. Do not invent research, user characteristics, product capabilities, or constraints.

**1. User needs**

Identify concrete user needs and classify each using the following categories:

* Functional/use-based need
* Usability/constraint need
* Emotional or meaning-based need
* Social/status or trust need

Use this table:

| Need | Category | Evidence | Confidence | Product/UI implication |
| ---- | -------- | -------- | ---------- | ---------------------- |

Tie each need to an observed workflow, product behavior, or documented user evidence. Do not write generic statements such as “users want an easy experience” without explaining the specific task or behavior involved. Do not force unsupported needs into the analysis merely to fill every category.

**2. User personas**

Create evidence-based personas for the important user types. Include no more than five unless the application clearly requires more; explain any exception.

For each persona, include:

* Persona name and role
* Situation or context
* Goals
* Jobs to be done
* Likely motivations
* Frustrations and barriers
* Technical confidence or access constraints, if evidenced
* Relevant permissions or account type
* Features and workflows used
* What success means to this persona
* Evidence and confidence

Label provisional personas and inferred attributes clearly.

**3. User goals**

State the outcomes each persona wants to achieve. Connect each goal to the relevant user needs and workflows, and explain what successful completion means.

Keep goals distinct from feature descriptions: explain the outcome the user seeks, then identify the features or workflows that support it. Include the supporting evidence and confidence.

**4. User stories and workflow requirements**

Write user stories in this format:

“As a [persona], I want to [perform an action], so that [I achieve an outcome].”

For each story, include:

* The related persona, user need, and goal
* The relevant feature or workflow
* Required data or inputs, where they come from, and whether they are already available, supplied by the user, or missing
* Required permissions, account type, and other prerequisites or dependencies
* How missing inputs or unmet prerequisites affect the user’s flow and the feedback they receive; distinguish existing behavior from proposed improvements
* Observable success criteria
* Supporting evidence and confidence
* Whether the current application supports the story fully, partially, or not at all; identify inferred or proposed requirements separately

Make clear what information is needed to analyze the users and what data a user needs to perform a particular task.

**Design writing rules**

* Focus on decisions about information hierarchy, navigation, task flows, interaction behavior, feedback, and user-facing constraints.
* Describe data and permissions in terms of what users need to see, supply, or access to complete a task.
* Keep existing behavior, inferred needs, and proposed design improvements clearly distinguished.
* Make recommendations traceable to the relevant needs, personas, goals, or stories.
* Keep the brief concise, specific, and actionable for product and interface designers.
```
